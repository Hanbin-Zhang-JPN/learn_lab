# 07｜效果不理想时：按这个顺序排查

不要一次改很多参数。每次只改一项，留下生成样例作比较。

1. **故事完全乱码**：确认训练 loss 明显下降；若只跑了 `--tiny`，它只是测试代码通路，不能用于成品。
2. **只重复同一句**：生成时把 temperature 从 0.65 调到 0.85，或把 top-k 从 12 调到 24。
3. **句子经常断裂**：先确认训练没有被 Mac 休眠打断。若默认训练结束时验证 loss 仍在稳定下降，可用 `python -m monogatari_llm.train --steps 4500 --time-limit-minutes 120` 从随机权重重新训练一轮；当前版本不会接着旧检查点续训。
4. **文风过于模板化**：先扩充 `data.py` 的原创部件，而不是放大模型。变化来自数据。
5. **训练超过 90 分钟**：程序会在 85 分钟停。关闭占用 GPU/内存的程序；确认 `00_check.py` 显示 MPS；不要把 batch size 调大。
6. **罕见姓名变成未知字符**：故事开头由原输入直接保留，但模型无法理解没在词表出现的字。把常用字符加入训练姓名或地点，重新训练。
7. **验证 loss 先降后升**：继续训练未必更好；脚本已经保留验证 loss 最低的检查点。
8. **四种作风读起来差不多**：先确认训练数据是新版，JSON 每行都应有 `"style"`。固定同一姓名和地点生成四次；若仍难区分，先扩充对应作风的句子部件，再从零训练。

评价时固定若干组姓名与地点，并让每组遍历四种作风。比较：是否包含输入、作风是否可辨、是否有完整结尾、重复片段比例、人工阅读是否自然。只挑最好的一条展示，会高估模型。
