# 从这里开始

这份说明假设你几乎没有编程经验。现在不需要理解所有命令，只需要知道怎样安全地试一次。

## 1. 什么是“仓库”

仓库就是一个有固定结构、能记录修改历史的文件夹。`README.md` 是封面，`docs` 是课本，`src` 是我们真正写的程序，`tests` 是检查题。Git 会记录文件怎样变化，但不会自动把内容上传到互联网。

## 2. 在 VS Code 中打开

1. 启动 VS Code；
2. 选择“File / 文件 → Open Folder / 打开文件夹”；
3. 选择 `LLM_monogatari`；
4. 若 VS Code 询问是否信任作者，只在你确认打开的是本仓库时选择信任；
5. 选择“Terminal / 终端 → New Terminal / 新建终端”。

终端提示符最后应当能看到 `LLM_monogatari`。用下面的命令确认：

```bash
pwd
```

## 3. 第一次运行

```bash
make start
```

它先在本文件夹内准备 `.venv`，再运行第一个分词实验。`.venv` 像一个只属于本项目的工具箱，不会替换 macOS 自带 Python。

## 4. 看懂第一个结果

输出会展示同一句日文怎样被切成字符，以及 BPE 怎样反复合并常见相邻单位。打开 `examples/01_tokenization.py`，改一行文字，再运行 `make lesson N=1`。第一次学习的目标只是建立“改文件 → 运行 → 看结果”的循环。

## 5. 看见错误怎么办

错误信息从最后一行往上读：最后一行通常是错误类别和直接原因。先记录三件事：

```text
我运行了什么命令：
最后三行错误是什么：
我刚刚改了哪个文件：
```

不要为了消除错误而复制一串看不懂的管理员命令，也不要使用 `sudo pip install ...`。本项目所有 Python 安装都应发生在 `.venv` 中。

## 6. 什么时候下载模型

前七课都不需要。等你能用自己的话解释 token、向量、loss 和 causal mask，再进入第 8 课。模型和训练依赖是本仓库最大、最慢、最像黑盒的部分，晚一点引入反而学得更稳。
