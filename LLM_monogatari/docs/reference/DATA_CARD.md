# 数据说明卡

## 数据是什么

`data/source/story_cards.jsonl` 含 36 篇短小日文故事卡，每行有 `name`、`place`、`story`。它们是为这个教学仓库逐篇编写的起跑样本，没有抓取网络小说，也不来自私人聊天记录。

`scripts/prepare_data.py` 固定随机种子 42，生成 28 篇训练、4 篇验证、4 篇测试数据。生成文件放在 `data/processed`，不提交 Git，因为随时可由源数据重建。

## 为什么只有 36 篇

这套数据的第一目的，是让新手在一台 16GB Mac 上确认“校验 → 划分 → 训练 → 评测 → 网页”的完整路径。它不是成品语料库。数量少让每一篇都能被读完，也让过拟合更容易被看见。

## 已知偏差

- 多为安静、怀旧、轻微奇遇的第三人称故事；
- 地点以日本旅游城市和景观为主；
- 句长、两三句结构和积极结尾较集中；
- 人名读法、性别和时代感未系统标注；
- 没有覆盖冲突、对话、幽默、方言等多样体裁；
- 地点只是故事背景，不保证地理或文化细节准确。

这些偏差会成为模型风格。若不喜欢，应先改数据，而不是只改提示词。

## 扩充规则

1. 只加入自己创作或明确有权使用的文字；
2. 不使用真实朋友的全名、住址或私人经历；
3. 每篇都让人名和地名自然出现；
4. 目标 120–260 日文字符，允许少量合理例外；
5. 每增加 20 篇，检查开头、结尾和意象重复率；
6. 新测试集先封存，不能边看输出边改同一测试答案；
7. 记录新增日期、作者/来源与修改理由。

## 不应做的事

- 把版权不明的小说整批复制进来；
- 用生成模型批量造数据而不逐篇阅读；
- 为追求低 loss，把验证或测试样本混回训练；
- 因为文本短，就认为其中不可能有隐私或偏见。
