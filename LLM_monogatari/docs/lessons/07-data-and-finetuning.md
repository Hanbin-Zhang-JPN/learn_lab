# 第 7 课：微调改变了什么

预训练让模型从大量文本学习一般的下一个 token 分布。监督微调再用较小、结构明确的数据调整行为。我们的样本形如：

```json
{"messages":[
  {"role":"system","content":"写一篇短故事……"},
  {"role":"user","content":"人物名：葵\n場所：鎌倉"},
  {"role":"assistant","content":"雨上がりの鎌倉で、葵は……"}
]}
```

系统、用户和助手角色最终仍会被 tokenizer 的 chat template 拼成 token 序列。`mask_prompt: true` 让损失只计算最后的助手回答，避免训练预算花在复述输入格式上。

## LoRA 的直觉

完整微调会更新大权重矩阵 W。LoRA 冻结 W，只学习两个低秩小矩阵 A、B：

```text
W' = W + scale × B A
```

若 W 是 1024×1024，完整更新约一百万参数；rank 为 8 的 A/B 合计约一万六千参数。它不是把模型“压缩成八个参数”，而是在受限的低秩方向上修改特定层。

4-bit 基座加 LoRA 常被称为 QLoRA：冻结的基座用低比特存储，适配器通常仍用更高精度训练。量化节省内存，但数字更粗糙，也引入量化方案和 kernel 这一层工程复杂性。

## 数据先于轮次

仓库提供 36 篇人工故事卡，足以验证管线，不足以声称风格成熟。逐步扩到 100–300 篇时，优先检查：

- 人名、地名是否真的自然出现，而非机械首句；
- 开头、转折、结尾是否多样；
- 有没有不想让模型模仿的套话；
- 长度、标点与叙述视角是否符合目标；
- 内容是否是你有权使用的；
- test 组合是否从未用于改写训练样本。

不要用另一个模型批量生成几百篇后不读就训练。那会让数据量看似增长，实际把同一种腔调、错误和结构复制得更牢。本项目的源数据是一行一篇，目的就是让你能够逐篇审稿。

## 历史坐标

迁移学习早于大型语言模型。预训练表示在 2010 年代逐渐成为 NLP 常规路线；2018 年 BERT 展示预训练后为多任务微调；2020 年 GPT-3 强调规模与上下文学习；2021 年 LoRA 提出低秩适配；2023 年 QLoRA 展示量化基座上的高效微调。

便利不等于无代价。参数高效微调降低单次实验门槛，却仍继承基座的数据来源、偏见、许可与未知行为。adapter 很小，也不能独立运行，必须配合兼容基座。

## 运行数据检查

```bash
make data
head -n 1 data/processed/train.jsonl
```

脚本固定种子 42，因此每次划分相同。修改故事卡后必须重新运行 `make data`。
