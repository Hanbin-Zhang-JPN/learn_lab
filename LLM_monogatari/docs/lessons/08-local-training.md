# 第 8 课：在 M3 上完成一次训练

这一课第一次引入较大的外部依赖和模型下载。开始前保存工作，接通电源，并关闭占内存很大的应用。MacBook Air 没有风扇，长时间高负载时降频是正常保护，不是训练失败。

## 0. 读配置

打开 `config/lora.yaml`，逐项确认：

- 模型：`mlx-community/Qwen3-0.6B-4bit`；
- batch size：1；
- max sequence：384；
- 微调最后 8 层的 Q/V 投影；
- rank：8；
- 训练 300 iteration；
- 输出：`adapters/LLM_monogatari-lora/`。

不要在第一次实验同时改变多项参数，否则结果变化时无法判断原因。

## 1. 安装训练工具

```bash
make train-install
```

本仓库固定 `mlx-lm==0.31.3`，因为命令与配置格式会随版本变化。安装内容是开源的，但远大于前七课的标准库代码。

## 2. 留下基线

首次模型下载可先用基座网页：

```bash
PYTHONPATH=src .venv/bin/python -m llm_monogatari.web --base-only
```

记录六组固定输入的输出，按 `Control + C` 停止。没有基线，就无法知道微调是改进、退步还是毫无影响。

## 3. 数据与训练

```bash
make data
make train
```

终端会定期显示 train loss 和 validation loss。看趋势而非迷信单个波动：

- 两者一起下降：还在学习可泛化模式；
- train 降、valid 持续升：可能过拟合；
- 两者几乎不动：学习率太小、目标已很容易或数据/遮罩有问题；
- 出现 `nan`：先停止，检查版本、学习率、数据长度与系统内存。

训练可用 `Control + C` 停止。adapter 目录里的 checkpoint 比控制台截图更重要。

## 4. 比较，不挑樱桃

```bash
make evaluate
```

脚本用六个没有出现在训练卡中的组合，分别生成基座与微调结果，保存到 `runs/`。请给另一位会日文的人看隐藏标签的 A/B 文本，评分：输入遵守、自然度、完整性、模板化。六题仍很少，但比只展示最满意的一篇诚实。

## 5. 怎样进行第二次实验

先复制第一次的配置和评测记录，再只改一个因素。例如：把人工审过的数据增至 100 篇；或保持数据不变，把 iteration 降到 200。记录假设、变化和结果。

不要先上更大模型。0.6B 若学不会清晰固定的窄任务，常见原因是数据、格式或评测，而不是参数不够。1.7B 4-bit 也可能在 16GB 上运行，但训练余量和热负载更差，不适合作为第一次闭环。

## 完成标准

保留一次基线、训练日志、adapter 和人工评分；能说明第二次实验只改变了什么；没有用 test 结果反复改写同一批数据。
