# 第 1 课：文字怎样变成 token

模型不直接看见“葵”或“鎌倉”。它接收整数编号。分词器决定一段文字被切成哪些单位，再把单位映射为编号。

## 为什么日文是一个好问题

英文句子常有空格，日文通常没有明确词界。`葵は鎌倉を歩いた` 可以按字符、语言学词素或统计子词切分。没有唯一“正确”的切法：切分方式是在词表大小、序列长度、未知文字和计算成本之间做选择。

字符分词最透明：

```text
葵｜は｜鎌｜倉｜を｜歩｜い｜た
```

它几乎不会遇到未知日文字符，但序列长，也没有把常见单位 `鎌倉` 当成整体。整词分词序列短，却会让罕见人名和新词掉到未知词。子词方法位于两者之间。

## BPE 的核心动作

Byte Pair Encoding 原本是压缩方法：反复把最常见的相邻符号合成新符号。后来神经机器翻译把它用于开放词表。假设语料是：

```text
物 語 を 読 む
物 語 を 書 く
物 語 の 種
```

`物 + 語` 最常见，就合成 `物語`。重新计数，再合并下一对。训练阶段得到“合并顺序”；编码新句子时必须按同一顺序应用。

运行：

```bash
make lesson N=1
```

再打开 `src/llm_monogatari/tokenization.py`。先读 `SimpleBPE.train` 的循环，再读 `encode`。你会发现真正的核心不到四十行。

## 历史坐标

- 1994：Philip Gage 描述 BPE 压缩算法；
- 2012：WordPiece 被用于日英语音识别；
- 2016：Sennrich 等把 BPE 系统用于稀有词的神经机器翻译；
- 2018：SentencePiece 强调直接从原始句子训练、语言无关；
- 随后，大型生成模型普遍采用 byte/character 与子词相结合的方法。

历史并不是一条“更聪明算法不断取代旧算法”的直线。BPE 胜在工程上的开放词表与效率，不代表它找到了语言的自然原子。一个词被切成更多 token，会带来更高计算成本；不同文字系统、方言和罕见名字也可能承担不均等成本。

## 三个容易混淆的概念

1. token 是切分后的单位；token id 是它在词表里的整数位置。
2. tokenizer 不是模型。换 tokenizer 通常意味着嵌入矩阵也要重训。
3. token 数不等于字符数，更不等于词数。价格、上下文长度和训练长度常以 token 计。
